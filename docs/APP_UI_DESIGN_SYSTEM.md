# App UI 设计规范

更新：2026-10-24。范围：现有 App 的渐进视觉统一，不扩展业务功能。

本文是源码实施的规范入口，与 [实施计划](APP_UI_IMPLEMENTATION_PLAN.md) 配套。最新页面、组件、部件属性及显示模式图稿作为视觉参考；原型中的示意账号、数据、权限及功能可用性不是产品事实。原型服务不属于 App 依赖。

## 1. 设计原则

1. **一张卡表达一个实体、任务或紧密相关的一组能力。**卡内依靠对齐、间距和必要分隔线分层，不套多层同级卡，不用大面积空白填满首屏。
2. 页面有明确主操作；低频配置渐进展开。简化常态说明，不删除错误、权限、来源、新鲜度和危险后果。
3. 同级入口统一线性图标、名称、右侧值和箭头锚点；表单字段不强制加图标。箭头意味着可进入，不装饰不可操作项。
4. 界面优化复用现有设备目录、Manifest、State、别名、请求与版本保护。不得重新创建连接、增加轮询、扩大能力或绕过权限。
5. 原型、源码、构建、浏览器验收、原生验收与部署分开记录，不用截图数量代表实施进度。

## 2. 视觉基础

### 2.1 颜色与主题

复用 `src/theme/ui-theme.scss` 的 `--blinker-*`、Ionic 语义变量；组件继续使用原 `--ui-*`，不建立第三套独立调色源。下表是已确认图稿参考值，不要求本批全局替换现有主题。

已迁移页面通过 `_settings-surface.scss` 显式启用这组外壳语义值，并同步本地 Ionic 页头/表面变量；不修改旧页面全局配色。真实 App 的旧 `_light/_dark` 外壳与组件主题是不同消费者，验收须同时检查编译页，不能只用 `ui-theme` 静态夹具代替。旧引擎不支持 `light-dark()` 时沿用原主题，另列兼容短验。

| 语义 | 浅色参考 | 深色参考 | 源码映射 |
|---|---|---|---|
| 页面 | `#f2f3f5` | `#111215` | `--blinker-bg` |
| 表面 | `#ffffff` | `#202226` | `--blinker-surface` |
| 主文字 | `#202124` | `#f2f2f4` | `--blinker-text-primary` |
| 次文字 | `#64666c` | `#b0b2b9` | `--blinker-text-secondary` |
| 分隔 | `#ebebed` | `#32353b` | `--blinker-divider` |

普通正文和辅助正文目标对比度至少 4.5:1，必要控件边界与焦点至少 3:1；装饰线不能独自承担状态含义。浅深色分别核对合成结果，不根据表格宣称已通过。

### 2.2 尺寸、文字和动效

- 使用 `4/8/12/16/20/24/32px` 节奏；分组卡圆角 22px，输入框 12px，主要按钮 16px。首页设备卡和特殊绘图控件保留其专属几何。
- 普通设置内容最大宽 720px，手机横向留白 16～20px，同级组间 16px；实际页壳沿用安全区，禁止复制原型手机外框或状态栏高度。
- 设置行最小高 56px，独立输入和操作默认最小热区 48 CSS px；图标可以小于热区，不靠相互覆盖扩大点击区。CSS px 检查不等于原生 pt/dp 或全部无障碍认证。
- 外壳使用系统 sans-serif，二级标题约 17px，身份名 20px，行标题 15～16px，输入 16px，辅助 12～14px；关键风险不用极小字。数值可用 tabular-nums，不统一覆盖电子主题字体。
- 设备／发现／工具／我的四主标题复用同一层级：正常根字号16px时29px，≤360px时27px，字重650、行高1.2、字距−1px；以rem随文字尺度增长，统一左锚点和基线。仅四页头显式启用`home-tab-header`，不改变登录或二级页标题。普通页头操作热区48×48px，首页编辑×／✓保留原44×44px合同。
- 长名称、长值和大字优先换行、增高；不能缩小热区、裁掉唯一说明。320px、小屏、横屏、大字、键盘和安全区单独检查。
- 浮层导航的圆角外应透出实际下层页面，不叠全宽实色／渐变底板；栏内仍保留可读的不透明表面。圆角卡片按自身边界绘制背景，子图像不得露出方角；不要用全局透明背景或裁剪全部内容掩盖局部问题。
- 可见 focus、可访问名称、原生按钮/单选语义、禁用和忙碌状态完整；选中不能仅靠颜色。减少动态效果时关闭非必要动效。

基础样式采用显式 opt-in mixin/组件选项，禁止全局 `.card`、`button`、`input` 或深层覆盖造成旧页面、控制组件、iframe 串样式。

## 3. 信息架构

主导航仍为设备、发现、工具、我的。个人区域不是新的家庭模型。保留现有路由、部署开关、权限和返回草稿行为。

| 页面家族 | 分组与主次 | 不变边界 |
|---|---|---|
| 发现推荐 | 横向灵感卡＋产品预览；五个发现分类保留 | 推荐保留真实分类角标；“智能灵感”分区只精选对应类，查看全部切同页对应分类 |
| 发现分类列表 | §25：B图文目录，隐藏每项重复的当前分类名 | 只渲染当前页，不无限追加；各类记住页码与位置；总页数／跳页仅在数据源支持时开放 |
| 我的/账号 | 身份与权益 → 设备管理 → 连接与服务 → 支持 | 自建服务、第三方服务、消息/设置可达，额度来自服务 |
| 设备设置 | 设备摘要 → 显示与布局 → 功能与管理 → 低频接入信息 | 名称、图片、Key、共享、任务、数据和调试均沿原门控 |
| 自动化/定时 | 一条规则/任务一张完整卡；编辑字段按任务分组 | 保存、启用、Start、执行结果不同义，CAS/UNKNOWN 不变 |
| 数据/记录 | 读数、单位、曲线、时间与来源同组；记录另组 | 状态历史、周期趋势、云端控制投递记录不混称 |
| 添加/配网 | 一步一个明确任务和真实结果 | 发现、认领、创建、获取 Key、配网分别确认 |
| 分享 | 当前设备上下文与全局分享分开 | 查询、控制、编辑、管理权限独立；撤权沿原链路 |

自动化、任务及数据页显式引入 `workflow-surface`，复用设置页的语义token与基础卡片／字段／按钮；每条规则或任务独立成卡，不在列表外再套同级总卡。编辑按名称、条件／何时、动作、定义状态分组；辅助来源用次文字，关键错误和未确认结果不折叠。

发现页不机械替换为原型旧单列文字卡：图文卡标题15px、横条标题16px、说明14px、辅助12px是根字号16px的起点，实际以rem增长和自然换行。分区间距24px，卡内12～16px；空间不足优先重排，不压成9～11px字。分类为原生按钮组，以按下状态和下划线共同标识选中，搜索同时作用于灵感／产品，空结果只出现一次。本地示例明确标注，不显示未经验证的浏览量、确定上市日期或没有动作的箭头。原型分类／搜索可仅为清楚标明的交互示意，不能拿它代替App筛选通过证据。

确认、刷新中与刷新失败分别显示；后台刷新失败不能抹去已确认结果。任务容量与来源、设备确认、技术耗时、UNKNOWN各自分层；保存定义、启用定义、Start和到期回调不得混称“执行成功”。低频技术字段可折叠，未知请求的查询及明确恢复入口必须保持可达。

状态历史、在线趋势与云端活动各有来源摘要及可展开限制：基线不是用户操作，选样归档不是固定设备上传，ACK不是State或实物完成。未启用、空、读取失败和待确认不以同一空态代替；改变时间输入不代表已经查询新范围。数据和任务操作在正常流内布局，不能用固定底栏遮住大字字段与焦点。

添加／配网页面沿既有步骤分组，设备发现、认领、创建Key、安全会话、网络配置和最终接入分别反馈。重新配网的身份核对及凭据失效后果、原生不可用、失败与恢复入口常显；仅技术说明和示例渐进展开。密码、SSID和Key保持精确输入，完整长值可读／复制，不用省略号截掉唯一信息。

分享管理区分待处理邀请、账号成员与本机公开收藏；当前设备分享和接受邀请保持各自上下文。控制权、编辑控制台、公开只读链接分别表达，权限和部署关闭时不宣传不可用功能。链接／权限弹层显式承接同一主题与安全区，沿原确认、忙碌与失败草稿链路，不新建自动提交行为。

工具首页复用设置型分组菜单和同级线性图标；可进入项保留箭头，规划中项保留状态标记及原解释提示，不伪装成可用路由。主tab仍按原64px页头／底部tab预算，不能套用普通工作流的56px页头或重复安全区。

个人支持页沿用既有设置表面，不另设阴影／渐变卡片体系。第三方服务按原天气／地理两组组织，输入与显示密钥／清除目标保持48px，验证中、验证失败和已保存保持原独立语义；不因视觉优化改Key规范化或验证协议。关于页保留完整简介、能力说明与原协议弹层，窄屏纵向展示、宽屏可并列；说明不省略。主操作按压时必须同时核对背景与对比文字，不直接继承中性按钮按压底色。

反馈沿用类型／内容分组和原本机草稿；标签、说明、计数按正常流展示，计数不压在输入上，窄屏／大字不裁类型说明。提交中、失败可重试与已接收是不同状态，服务端已接收的partial不冒充全失败。消息列表将时间置于正文下方，删除独立48px目标；标题自然换行，摘要可有界两行、详情正文完整。消息部署关闭不为视觉检查开启，打开未读详情会标记已读，软件验收只能用本地替身覆盖相关写操作。

## 4. 三层渲染所有权

| 层 | 统一内容 | 禁止改动 |
|---|---|---|
| App 外壳 | 导航、安全区、入口、状态反馈、字体层级 | 不重复 `ion-content`、设备连接或租约，不给整个面板加总外卡 |
| 组件模板 | 同族比例、标题/读数/操作/反馈对齐、既有主题 token | 保留 7 类型、23 外观、48 预置；不自动重排/删减已有文档 |
| Agent 自定义面板 | 通过现有运行时协调设计语言 | 保留文档主题、编排、滚动、sandbox/CSP/channel/动作校验；父 CSS 不穿透 |

保存的 `widgetId/type/variant/endpointKey/extraKeys/grid`、顺序、选项、绑定和主题逐项保留。新建默认规格与已保存布局是两种合同；打开设置、切换模式不触发布局迁移。

## 5. 首页卡片与控制组件

### 首页

- 标准卡高不超过自身宽，长卡与同行标准卡等高；设备图尺寸和相对锚点一致，长卡右侧首版留白。
- 名称左上、通道状态右上，底部最多一行透明数据/控制块；容量不足降列或显示既有更多入口，不丢绑定、不强塞滑条。
- 长按进入页面级编辑，左 × 取消、右 ✓ 保存；整卡拖动，点击进入统一设置。编辑零设备命令、取消零落盘，沿既有草稿机制。

### 控制组件

- 保存8栏文档与原坐标，横纵使用同一网格单元；2×2固定规格实际为1∶1。每个网格按自身内容宽（不是外层页面或iframe宽）选择断点：≤660px按4个逻辑单元显示，2栏半行、4／8栏均整行；更宽时按8单元显示。两轴及嵌套分组统一gap12，8单元下2栏卡最窄约156px。4／8在窄屏同宽须在属性中明确，不用固定78／84px行高冒充比例。
- 紧凑条、读数、表单及绘图原子都遵守所选外框；空间不足使用有界内容滚动，不偷偷改高度或缩小热区。错误在卡外正常流，可推迟后续行但不能拉高同行卡壳。普通HTML自定义卡仍由文档内容决定，不将所有组件强制方形。详见[几何修复合同](APP_UI_GEOMETRY_AND_COVERAGE_REPAIR_PLAN.md)。
- 标题与状态中线一致，读数/单位分级，操作占剩余空间，反馈在卡内正常流；保留开关、按钮、按住、长按确认、选值与发送的行为差异。
- 工作台大字单列是待验证候选，不自动写回 grid；保留自然、暗夜、电子主题和专用字体。
- 控制页与两个编辑页共用局部 chrome 几何，不覆盖主题 palette：56px 工具栏、48 CSS px 操作目标，内容偏移在页级连同安全区重算。48 CSS px 是本项目 WebView 目标，不等同于原生 pt／dp 或可访问性认证。
- 主题只覆盖 token，不给整块组件网格新增带内边距的总外卡。显示、编辑、属性预览和 Agent 运行时均按可用内容宽度选择网格断点。
- 小视觉不必等于小热区：渐变轨道保留6／14／32px视觉，操作带48px；文本发送保留32px可见圆形与独立48px目标。密集旧单行选项允许卡内有界滚动，全部选项可达，不缩小按钮、不改存储 grid。
- 属性／部件库是只读外观预览；主编辑器显式“预览”仍可真实控制，必须就地提示，不混称零命令编辑态。
- 按键／档位／色块采用独立48px目标，不通过相互覆盖扩热区：档位点保留30px视觉，色块保留26／36px视觉，加减保留40px视觉。密集旧规格仅对应键区／档位行／色板局部滚动，不改写保存尺寸或删除选项；轮盘扩大最小区域时沿原圆心及viewBox比例计算。

## 6. 部件属性

- 常用项先展示标题、说明、显示标题及只读绑定摘要；外观／图标／色调／尺寸单独折叠，当前外观参数直显，低频映射及告警等归入高级；原始 JSON 再折叠且只读。分组来自原参数目录，保留全部现有参数，不以代表图替代完整目录。
- 打开不改尺寸；用户切换外观才按原规则适配允许规格并清理不支持的选项。不能把每个旧模板重新初始化。
- 字段 key 只读；显示 min/max/scale/warn 不改变 Manifest 的范围、step 或协议。额外绑定数量及顺序沿原合同。
- 布尔选项有默认/开/关三态；默认图标与未设置是同一语义，原型 sentinel 不序列化。空数值不等于显式 0。
- 保存仍是整个面板保存，包含父编辑器其他草稿；返回丢弃属性副本。失败保留属性输入并恢复父客户端文档／绑定／undo／dirty；不宣称回滚已提交的服务端布局或 revision。
- Inspector 显式上送 invalid；两个真实保存入口同时禁用按钮并在方法内禁存，不能静默退回旧有效值后继续保存。非法原文及 IME 组合输入留在局部草稿，其他合法编辑或同一部件回显不清除；新编辑会话才重置。
- 标题沿用 64 UTF-8 字节合同，与解析器共用上限；输入时按去首尾空白后的标题校验，不再用32字符截断。显示字节数及就地错误，留空使用原名称；不截断或迁移已保存标题。
- 表单沿用三主题 token，48px 热区、关联错误和显式“查看错误”定位；不因输入失败反复抢焦点。换外观清除不适用参数时，同一用户事件内先更新有效性再输出部件；不异步放松保存门控。

## 7. 显示模式

- 左侧组件面板、右侧自定义面板，并列页面缩略示意；当前使用与草稿选中分开表达，点选不保存，明确确认后应用，取消不应用。
- 两套内容独立保存，切换不清空布局、顺序、绑定或自定义文档。组件模式不被灯具示例替代。
- 所有者复用原设备配置保存；共享用户只保存本机偏好，不改变所有者配置或取得编辑权限。
- 缺自定义文档：所有者进入既有创建入口，共享用户禁选并说明。不能将创建入口表述为已成功切换。
- 首批生产预览是清楚标注的**布局示意**，不伪装成真实读数/用户文档，不实例化两个可交互面板、不新增实时订阅或 iframe。
- 保存失败保留选择及就地错误；离页、换账号/设备后旧草稿失效。已发请求不宣称被取消/回滚，旧结果不能关闭或污染新选择器。

## 8. 真实反馈与验收

加载、空、失败、只读、缓存、陈旧、未同步、已确认和 UNKNOWN 分别处理。ACK 不等于 State，也不证明物理完成。任务保存/定义启用/Start 沿既有语义，未知请求只读核对，不自动重放。

每批检查权限与部署关闭、浅深色、小屏/横屏/大字、触控/键盘/安全区、取消/保存/失败保留，以及已有布局/绑定不变。浏览器验证不替代原生生命周期、存储、真实 ACK/State 或同事签收。

低频工具同样按原流程分组：范围／输入、目标／结果、执行状态与恢复操作分开呈现；状态不只依赖颜色，窄屏不隐藏“解析中”等必要信息，错误、长地址及文件名自然换行。两OTA共用局部呈现mixin，不共享或重造传输状态；等待、失败、取消与成功保留各自原语义。固定主色渐变、微小字号和整段省略不作为工具页独立风格；表单、操作及焦点继续复用现有相对字号和48 CSS px口径。视觉迁移不开放部署门控，不自动扫描／认领／上传／重试未知写入；继续确认、恢复与进入详情是否有副作用必须先按真实方法核对。§38只完成四页有限软件验证，未覆盖BLE调试、公开控制台或设备更新全家族。

原生返回先交给现有弹层／菜单，再处理页面导航；同一路由内的编辑草稿也要接入路由退出保护，复用原确认、取消及作用域检查。页面需自行显式声明实际使用的Ionic组件，不能依赖此前访问其他页面恰好注册了输入／选择等元素。

透明页头之下的表单必须按实际可见滚动viewport验证原生IME焦点，只有初始留白或scroll-padding不等于键盘已避让。禁止拖动与禁止编辑／控制是不同语义；拖动所有者只在布局态挂载，退出时还原其占用的可访问属性，不将整卡标为禁用而误伤子操作。

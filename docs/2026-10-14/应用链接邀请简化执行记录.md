# 应用链接邀请简化执行记录

## Intent：最终目标

根据用户最终选择，仅保留 App 邀请链接；撤回本轮邮件邀请实现，完成未登录打开、登录后继续和刷新恢复的领取链路。

## Data：可用证据

- 用户确认“只保留 App 邀请链接”。
- 现有邀请服务已支持有效期、幂等创建、撤销、角色及编辑权限、单次领取后的账号绑定。
- 本轮核实 local 登录验证码仍转发至 `https://api.yiyu.pro` 的 Auth；没有修改该登录方式或远端部署。

## Edges：边界与限制

- App 链接为 `diandeng://share/<code>`，也可在“设备共享”右上角 + 粘贴链接或邀请码。
- 没有新增 HTTPS 网页托管、Universal Links 域名关联或邮件发送。
- 邀请不限制目标邮箱；领取人需要登录，链接首次领取后绑定该账号。
- 已有定向邀请的读取、接受和拒绝保持兼容；当前 App 不再创建邮箱邀请。
- 未新增测试用例、未调用浏览器进行 UI 确认、未发送真实邀请邮件、未更新线上 Auth。

## Answer：交付结果与成功标准

### 保留的实现

- 移除“邮箱邀请”按钮、邮箱输入弹窗和前端创建参数，只保留“邀请链接”。
- 保留权限选择、复制完整 App 链接、撤销邀请及成员管理。
- 原生链接和粘贴入口统一进入带 code 的领取路由；刷新后可重新核对邀请。
- 登录回跳参数保留 code；邮箱验证码登录或自动注册后继续原邀请。
- 初次匿名登录完成后重新核对邀请；切换已有账号仍清除旧确认状态。
- 旧邀请页离场时识别当前仍在邀请路由内，避免清空新邀请。
- 创建失败提示优先读取拦截器规范化后的 `error.code`。

### 撤回核对

- `aily-services` 仓库状态恢复干净，新增 Auth 邮件接口和路由修改已删除。
- 新增 Gateway 邮件客户端、worker、043 迁移、构建产物及相关配置已删除。
- Gateway 恢复原邀请处理链路，同时保留本轮之前完成的控制台共享和编辑权限功能。
- 实际本机数据库最大迁移版本为 42，没有执行邮件迁移。
- 先前公开分享开关、浏览器公开链接、本机收藏及共享页样式调整保留。

### 验证

- App local 构建与 Gateway 构建通过。
- 33 项相关前端现有检查通过，覆盖共享服务、启动登录和请求拦截器。
- 38 项相关后端现有检查通过，包括邀请授权、跨分片、预览、历史定向邀请、HTTP 和既有共享 E2E 检查；数据库检查使用临时隔离 schema。
- 两个已有前端测试仍使用过期的扁平 mutation 返回值，已改为断言现有 `share` 包装结构并修正离开共享的响应 fixture，没有新增测试用例。
- 后端 E2E 首次运行的临时目录缺少 TypeScript 编译产物；补齐本次构建产物后该检查通过。
- 前后端 `git diff --check` 通过。
- 本机 App 4200 预览已重新启动，HTTP 200；Gateway 17000 的 healthz 返回 200。

## 架构与数据流

架构图和数据流图见同目录《应用链接邀请简化计划》。邀请授权仍由现有 IoT Gateway 处理，登录认证沿用已有 Auth。

## 自我批判

- 邮件方案会引入跨服务部署和额外凭据，而用户最终只需要可分享的 App 链接；已完整撤回该探索，避免留下闲置邮件实现。
- 用户需要的“无需发邀请邮件”与“无需验证码登录”不是同一件事，当前交付保留已有登录方式，并明确说明区别。
- 没有以取消邮箱校验的方式把邮件邀请变成开放领取；最终直接复用原有普通链接邀请模型。
- 构建与现有协议检查不能代替真机 App 唤起、剪贴板和视觉验收；本轮未声称完成这些验证。

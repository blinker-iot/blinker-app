# 预览接入真实控制执行记录

## Intent：最终目标

预览模式通过设备组件控制中心已有通道实际操作板卡；添加部件完成后停留在画布。

## Data：实施证据

- 移除 previewValues。本地文本 draft 仍单独存放，卡片 value 直接读取当前字段回报。
- V2 动作经 DeviceUiPort.sendCommand(deviceName, key, value)，没有在编辑器选择或复制云端、LAN、BLE 通道。
- invoke、toggle、range、select、draft、commit 的处理与控制中心对应；数值提交校验有限值和安全整数。
- 字段级 pending 与 queued 保留发送中收到的最新后续动作，包括 hold 的释放。旧连接的迟到结果通过 pending 集合引用隔离，不修改新连接状态。
- V2 控制要求当前页面可见、应用前台、连接 ready 且未 aborted、Manifest 有效、stateFresh。离开页面或进入后台时释放连接，回到可见前台时重新建立失效连接。
- 旧协议按 widgetId 取实际绑定，复用 legacyCommand 和 DeviceService.sendData。旧协议访客设备沿用已有的本地模拟回报行为。
- 发送失败写入字段错误，在相应预览卡片下显示；不把发送函数返回当作板卡已执行。
- 移除 addedWidgetId 和 modal dismiss 后打开属性页的回调。添加成功仅关闭部件库，继续显示画布；点击编辑模式的组件仍可进入属性页。

## Edges：边界与限制

- 本次接入控制指令和现有属性回报订阅，没有复制控制中心的事件历史、遥测订阅或整套重连逻辑。
- 不主动向实际板卡发送验证命令；没有硬件往返实测。
- 未新增测试用例，也未调用浏览器。
- 通信服务与其测试文件均未修改；额外检查暴露的旧测试不匹配没有混入本次功能修复。

- 额外执行 DeviceUiPort 现有 11 项测试，其中 3 项通过、8 项失败；总计 32 项通过、8 项失败。失败原因包括 mock 缺少 waitUntilReady／acquireConnectionDemand，以及仍断言旧 ensureReady 调用。确认通信实现、对应测试与 DeviceV2Service 文件没有本次差异，未掩盖失败或修改断言。

## 自我批判

仅将 action 接到 sendCommand 不够：本地模拟值会遮住真实回报，发送中的释放动作可能被丢弃，页面恢复后也可能持有失效连接。本次分别移除模拟值覆盖、保留逐字段后续动作，并在只读复核发现前后台问题后补齐可见页面的连接重建。构建和已有页面测试能提供静态与回归证据，但不能替代实际板卡控制验证；扩展通信测试仍有明确失败，不能宣称全部检查通过。

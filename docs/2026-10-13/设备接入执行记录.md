# 设备接入执行记录

## Intent：最终目标

让用户提供的 Device Key 所属设备通过真实 ESP32-S3 上线，供本地 blinker-app 读取与控制。

## Data：可用证据与执行细节

### 环境确认

- 用户确认 ESP32-S3 通过 USB 连接。
- esptool 识别为 ESP32-S3 revision 0.2、8 MB Flash、8 MB 内置 PSRAM，串口为 `/dev/cu.usbmodem3101`，使用 USB-Serial/JTAG。
- 只读匹配 Device Key 的 locator，确认对应本地 Gateway 的 active 设备 `Esp32 S3`，密钥状态 active。
- 逻辑设备 ID：`device_21ef8022-8d7c-4d46-92dd-f839e18b8126`。
- 正在运行的 App 使用 `ng serve --configuration local --host 0.0.0.0 --port 4200`。
- 本地 Gateway 公告地址为 `192.168.1.108:8883`；设备认证入口为同一主机的 17000 端口，健康检查通过。

### 构建与烧录

- 使用 blinker-library 的 WiFiQuickStart，工作副本存放在库的 `.build/device-connect-20261013/WiFiQuickStart/`。
- 凭据放入被 Git 忽略的 `secrets.h`，文件权限 600，工作目录权限 700；不在本记录中写入凭据。
- 仅为工作副本增加 USB 串口诊断入口；未改动 App 产品源码或库的受版本控制源码。
- 构建使用 ESP32 core 3.3.1、esp-x32 14.2.0、Arduino libs 5.5.0、esptool 5.1.0，FlashSize=8M、CDCOnBoot=cdc、PSRAM=disabled。
- 程序占用 1,010,087 字节，静态内存占用 49,888 字节，编译成功。
- 按构建分区表写入 bootloader（0x0）、分区表（0x8000）、OTA 初始化数据（0xe000）和应用（0x10000），hash 校验成功。
- 未执行整片擦除，未写入 NVS 分区。

### 接入结果

- 烧录前：设备 mqtt_online=0，Manifest 和状态记录不存在。
- 烧录后：设备 status=active、mqtt_online=1。
- Manifest revision=1，field_count=3：`power`、`buttonPresses`、`button`。
- 状态 revision=1：`power=false`、`buttonPresses=0`。
- 串口诊断：state=active、network=1、cloud=1、lastOperationError=0、productError=0、operationFailures=0、stateTransportErrors=0。
- 关闭串口监视后，在首次上线约 168 秒时再次只读查询，mqtt_online 仍为 1、status 仍为 active。例程没有周期性遥测，因此本次复核不声称状态 revision 持续增长。

## Edges：边界与限制

- 本次验证针对本地开发服务，不能据此宣称远程生产服务也能识别。
- 未使用浏览器确认 UI，未生成测试用例；设备在线和能力上报有后端及串口证据。
- WiFiQuickStart 的 power 是软件状态，未绑定板载 LED；button 动作由例程定义为计数加一。
- 例程仅在初始化与命令触发时回报状态；不能将静态状态记录误称为周期性遥测。
- 本地 Gateway 的局域网 IP 变化后，需要更新固件构建配置与后端公告地址。

## Answer：交付与成功标准

设备完成烧录、认证、MQTT 上线和能力上报。当前本地 App 可使用已有 Device V2 流程读取名为 `Esp32 S3` 的设备。App UI 实际显示未验证，用户可刷新设备列表后打开设备。

构建日志、烧录日志和固件位于库的 `.build/device-connect-20261013/`；包含凭据的产物不应提交到版本控制。

# 新设备默认自动适配执行记录

## Intent：最终目标

新设备没有组件配置时直接展示自动适配的控制中心，不自动进入调试工具。

## Data：实施证据

- DevicePage 缺省为正常组件页：BBP2 使用 DeviceV2，旧协议使用 Layouter2Component。明确选择的 component 与旧协议已保存 debug 视图仍保留。
- 移除 DevicePage 为推断 BBP2 显示模式而读取布局的依赖，布局由正常控制页加载。
- V2 正常页无记录或已保存布局为空时，通过 generateDefaultPageLayout 依据已接受的 Manifest 生成运行时组件。
- 空记录仍保留其 revision 和主题；Manifest 更新时自动视图跟随能力重新生成。进入编辑器也会从相同的自动组件开始。
- UIC 调试开关只依据明确组件选择或旧协议记录的 debug 状态，不再把 revision=0／没有布局视为调试开启。
- 两处关闭调试入口直接切回正常控制页，不再因没有保存记录跳转编辑器。
- 旧协议合法空面板进入已有的自动适配逻辑，保留主题；自动视图在首次数据稍后到达时重新读取本地能力生成组件，不重复访问云端。

## Edges：边界与限制

- 自动适配展示不会隐式保存服务端布局；非空已保存布局及用户明确选择的调试模式不被覆盖。
- 旧协议只沿用 showSwitch 和已有数值回报，不猜测可写字段。
- 尚未获得设备能力时仍等待数据，不构造虚假组件。
- 没有新增测试用例、浏览器确认或硬件命令验证。

## Answer：交付与验证

- 本地构建通过。
- 更新现有 DevicePage 测试中的旧默认调试断言及移除的依赖注入；原有布局、布局服务、DevicePage、DeviceV2Page、DeviceUIC 共 51 项通过。
- git diff --check 通过，临时测试配置已删除。
- 架构图和数据流图见 [执行计划](./新设备默认自动适配计划.md)。

## 自我批判

只修改默认路由仍会留下空白正常页，所以本次同时修正了无布局时的生成路径与旧设备首次数据到达后的刷新。自动展示和保存配置必须分开，才能保留版本控制与用户明确的调试选择。本次没有扩展至新设备创建 API，也没有通过改设备名称或演示数据绕过真实能力声明。

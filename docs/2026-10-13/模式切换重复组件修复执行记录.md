# 模式切换重复组件修复执行记录

## Intent：最终目标

确保调试模式返回组件模式时，仅在正确的容器中挂载一份组件页面。

## Data：可用证据与实现

- 根因路径：模式配置改变后，旧容器仍可能存在；销毁组件导致同步状态通知，父页变更检测替换容器，ViewChild 回调重新加载组件，外层调用随后继续创建第二份实例。
- 在 `src/app/device/device.page.ts` 增加 `loadingDevice` 标记，阻止加载过程中同步重入。
- 创建组件前执行父页变更检测，先完成模板分支及 ViewChild 容器更新，然后清空当前容器并创建组件。
- 使用 finally 解除标记，确保异常或提前返回不会阻塞后续加载。
- 本次产品代码仅修改设备外壳加载逻辑，未改动面板数据和组件布局。

### 验证结果

- `npx ngc -p tsconfig.app.json --noEmit`：通过。
- 现有 `device.page.spec.ts`：10 个测试全部通过。
- 默认测试编译受到既有 BLE 测试失效导入阻挡：`session.spec.ts` 引用未导出的 `BleDirectFrameChannel` 和 `BleDirectProtocolError`。使用临时 tsconfig 限定现有设备页测试编译范围后通过；临时配置已删除。
- `git diff --check`：通过。

## Edges：边界与自我审查

- 既有测试使用模拟容器，能验证设备切换、缓存页重入、配置回退和连接生命周期，但不能证明真实 Angular 容器切换的视觉结果。
- 按用户要求，没有新增测试用例，也没有使用浏览器进行 UI 确认；截图场景尚未在实际设备上复验。
- 加载标记仅覆盖同步加载区间，不引入定时器、全局锁或数据去重，不掩盖合法的组件配置。
- 创建前的变更检测用于满足模板容器切换这一实际依赖，不改动通信生命周期。
- 已有工作区改动保持原样；未顺带修复 BLE 测试问题。

## Answer：交付结果与成功标准

代码已阻止同步重入造成的重复挂载，并将模板容器更新放在动态组件创建之前。应用编译及现有设备页测试通过；最终视觉验收为实际设备连续往返调试模式与组件模式后，组件始终只显示一组。

# 最小自动化产品收口执行方案

更新：2026-10-10。M1～M5已按限定范围完成：新版App和Gateway迁移050在本机完成真实页面、两普通WiFi设备短闭环。第84批执行链路证据保留，不重复实现规则执行器；本机验收不等于全平台或生产发布。实际新版本结果见§8。

## 1. 范围与依据

保留现有范围：同账号、同租户及分片的两台普通 WiFi 设备；布尔变化和数值阈值作为条件，一个可写布尔属性作为动作。创建默认停用，用户明确启用；App 退出不停止云端规则。原基线、回差、30秒冷却、容量、权限与未知执行保护不变。

交互参考 [IFTTT 创建说明](https://ifttt.com/docs/applets)：简短标题说明用途，以触发和动作组织配置，隐藏不需要用户填写的技术字段。参考[米家联动使用手册](https://ics-resources.xiaomi.com/ics-resources/articles/60c308fcad904a4ba10aa587.html)：先选择条件，再选择设备动作，手动场景和自动联动分开。这些是交互依据，不是其内部执行架构的证明。

本批不增加多条件、多动作、延时、日历触发、脚本、按钮 Action、数值目标、BLE-only 或网关本地执行；不重新改造设备库、MQTT、BBP/2、Broker 或规则判定核心。

## 2. 用户流程

1. “我 → 自动化”直接进入规则列表；旧 `/scene-manager` 入口重定向到相同页面。
2. 列表展示名称、可理解的条件和动作摘要、启停状态及必要异常。提供新建、详情及明确标注的历史入口，不同时堆叠表单、技术说明和执行记录。
3. 新建按照“名称 → 当设备条件变化时 → 执行设备动作”组织；数值输入保留阈值和有效正回差，不猜测单位或填入适用于所有设备的默认回差。无能力缓存时引导先读取对应设备能力，不自动连接全部设备。
4. 保存得到停用规则，详情中明确启用。编辑现有规则可以修改名称、条件和目标值；本批源与目标端点保持原样，避免扩大端点迁移和能力恢复范围。
5. 编辑已启用规则必须明确确认，沿原 ID 和精确版本提交；不删除重建、不自动绕过版本冲突。编辑后重新建立基线的行为沿原实现，不把保存当立即执行。
6. 详情提供启停、编辑、删除及最近执行结果。删除沿用软退役，不能重新启用，历史不删除；已发命令不能被召回。
7. 保存结果未知时显示“结果待确认”，先核对原请求；恢复仍须明确确认原请求。ID、原版本和原请求正文收进技术详情，但不得隐藏真实未确认状态。

布尔条件使用“从关闭变为开启／从开启变为关闭”，不能改写为持续状态条件；数值条件使用“升至／降至阈值时”，继续解释离开回差区才允许再次触发，不因文案简化改变语义。

## 3. 名称持久化与兼容

公开 HTTP 管理合同增加可选 `name`，与设备协议和条件 policyVersion 无关。显式提交名称须为合法 Unicode 字符串，拒绝控制字符及未配对代理项；去除首尾空白后非空，最多80个 UTF-16代码单元，不做额外 Unicode 归一化。

- 新 UI 提交明确名称；旧规则、旧响应和旧持久意图没有该字段仍可读取。
- 旧规则没有名称时使用条件和动作生成展示标题，不批量回填数据库或把展示标题冒充已保存名称。
- Service 使用原规则表的 nullable `name` 与原始创建元数据 `create_name`，通过迁移050加入；不改 definition/digest/观察事实和命令帧。
- 省略名称的旧编辑保留当前名称。原创建重试核对初始名称，修改重试核对当前名称，版本冲突仍沿原合同。
- 名称与原条件更新同事务提交；App 在持久化新意图前完成校验，未确认的原意图不按新表单或新名称改写。原意图带名称时，确认结果必须同时匹配名称。

只改名仍沿原PUT／CAS增加definitionRevision并重新建立基线，不新增独立改名接口。新App与带名称的Service响应必须匹配升级；旧无名称数据兼容不代表旧APK的严格模型能够读取新命名规则。测试和部署状态必须分开记录。

## 4. 状态与信息分层

| 信息 | 普通页面 | 技术详情 |
| --- | --- | --- |
| 启停 | 已启用、已停用、已删除 | enabled、retiredAtMs |
| 执行结果 | 设备已确认、拒绝、未执行、结果待确认 | executionId、修订、内部状态 |
| 观察状态 | 初次等待设备状态、明确的执行结果未知 | 近期观察／等待观察恢复及原因边界 |
| 配置 | 设备名、属性名、条件、动作 | deviceId、属性 key、valueType、fingerprint、definitionRevision |

超过5秒没有新的观察样本并不能证明设备离线或规则停用。启停以服务器 `enabled` 为准；不能为了显示绿色增加心跳或持续采样。ACK表示设备协议确认，不承诺物理动作完成。没有源数据、未离开回差区和冷却期间不补触发，仍沿已有语义。

## 5. 模块与清理边界

App 保留 `contract → client（持久原意图）→ http → service → UI`。展示摘要与状态文案集中在 models，编辑器不执行规则、不发 MQTT、不重建恢复队列。单页面内部使用明确的列表／编辑／详情视图即可，不为三个视图创建新的业务框架。

旧场景只读归档，不能再把旧新建／编辑入口当成可运行云规则。替换路由后全源码检索确认旧编辑器、动作选择器和SceneService已无消费者，移除对应7个文件；DataService中的旧场景数据和只读归档保留。首页不显示旧 `sceneList` 的数量或伪造默认10条规则。未命名设备使用排序后的展示编号区分，不将编号作为设备身份或写入设备元数据。

设备主线和共同方案的当前状态表去掉“A2-4待实物”的陈旧待办，保留原批次、失败记录及测试证据。所有新测试分开记录软件与真机，不累加历史测试或以第84旧 APK 证明本批 UI。

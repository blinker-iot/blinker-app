# 设备列表卡片布局与编辑执行方案

更新：2026-10-19。DC1～DC5 基线、编辑交互修订及 DC6 限定收口已完成代表性 Android 短验。当前编辑顶栏仅 ×／✓，整卡拖动；底栏按最新要求只显示值／单位或控件，名称保留在设置与无障碍描述。已修复设备设置保存后首页仍使用旧偏好的实际缺陷，结果见末节。标准卡高度不超过宽度、长卡同行等高、设备图共用尺寸与锚点和原控制链路不变。此前 Android／Cloud 的 ACK／State、回收与精确恢复证据仍保留，不重复控制或刷板。本轮不提交推送，不扩展设备协议、定时任务、自动化或控制页编辑器，也不扩称全平台真机矩阵通过。

本次布局以用户最新纠正为准：**标准卡设备图下方最多一行，这一行可配置多个列小块；不是纵向多行，也不是 2×2。长卡优先保持设备图右侧简洁，首版留白，数据与操作集中在底部单行。** 前一轮关于标准卡纵向排列两至三个块、长卡右侧堆放数据的建议不再执行。

## 目标与边界

设备列表应能稳定地识别设备、判断可达性、查看少量常用数据和执行明确的快捷操作。调整卡片外观不应改变连接策略、权限或设备能力。

- 保留设备图的标准卡视觉基准。标准卡与长卡使用相同图像尺寸和相对于卡片左上角的位置，不随在线状态缩放，也不因切换长卡重新居中。
- 设备名放左上角，状态图标放右上角，常用数据或操作放底部单行。
- 长按进入页面级编辑，左上角 × 取消，右上角 ✓ 保存；进入后整卡可拖动，轻点卡片或小块进入同一个设置面板。顶部不显示编辑标题、选中设备名或尺寸／设置选项栏。
- 首页卡片是当前用户的展示偏好，不修改设备固件、设备能力、其他用户页面或同事维护的控制页布局。
- 复用既有名称元数据、Manifest、State、连接协调和控制链路。不另建 MQTT 连接、控制协议、实时上传租约或自由画布编辑器。
- 不升级 SDK、不扩槽，不默认刷板或改服务。DC5 按用户批准范围仅临时使用 COM11，先新鲜完整备份、验收后精确恢复；只启动既有本机容器，没有修改服务镜像或配置。不自动提交或推送 Git。

## 卡片布局合同

### 固定主体与底部单行

首页继续采用标准卡占一列、长卡占两列的外层布局。长卡仅扩展宽度，保留左侧标准卡的图像锚点；头部预留固定空间，长设备名不能将图像下推。

标准列实际宽度为 `S`，卡高为 `min(220px, S)`：手机窄列为正方形，较宽列保留 220 px 高度上限，高度始终不超过宽度。长卡宽度为两列加 12 px 间距，采用 `(自身宽度 − 12px) / 2` 得到相同的 `S`，不直接套 2∶1 而产生半个间距的高度差。设备卡片自身建立 inline-size 容器，首页与设置预览复用这套计算。

两种卡片共用标题高度 `max(24px, 1.1375rem)`、底栏高度 `max(44px, 10px + 2.0125rem)`。图像左偏移 14 px，上偏移为标题高度加 12 px，图像边长为剩余垂直空间与 92 px 的较小值；标题外壳与图像、图像与底栏外壳至少留 4 px 间隔。这里的外壳是资源和触控预算，不是可见内容的行高：底栏常规值／控件使用与顶部相同的视觉行高（默认 24 px），在至少 44 px 的操作外壳内靠下对齐，上下可见内容距卡边约 8 px；滑条保留数值加轨道的原复合布局。大字体继续按实际文字预算缩图，不撑高方卡、不换成第二行；未配置数据也保留相同的图像及底栏预算。

DC5 视觉修订统一设备名、数值和控件的字体家族，取消卡片数值强制点阵／等宽字体，保留数字对齐能力。设备名与状态图标在共用头部预算内垂直居中，不靠移动图标补偿。按本轮用户追加的简洁展示要求，底部小块保持透明，不再重复显示功能名称：只读显示值及单位，开关显示真实 State 驱动的 32×18 px 轨道，按钮显示触发图形，滑条保留数值／单位及轨道。名称仍完整用于设置面板、title 和无障碍描述；编辑态只展示静态内容并打开配置。整个操作块保持至少 44 px 点击高度；缓存、不可用、连接中及 ACK／UNKNOWN 的必要短反馈保留，不能因精简而隐藏风险。

```text
标准卡                         长卡
┌────────────────┐            ┌──────────────────────────────────┐
│设备名       状态│            │设备名                         状态│
│                │            │                                  │
│   设备图       │            │   设备图          首版留白        │
│                │            │                                  │
│26℃ │65% │ ○ │            │26℃ │ ○ │       40 ──●──       │
└────────────────┘            └──────────────────────────────────┘
       底部仅一行                         底部仅一行
```

示意只说明区域关系，不代表最终像素尺寸或要求标准卡在所有手机上容纳三个操作块。长卡右侧不增加另一组小块；后续若有明确用途，另行评估，不能为填满空白而堆数据。

1. 底部最多一行，按可用宽度提供二至四个基础列；较窄标准卡优先二至三列，长卡通常三至四列，基础列数上限为四。
2. 同一行各基础列等宽，列宽和行高由布局确定，不由标签、数值长度或在线状态撑开。一个普通数据块、开关或按钮占一列。至少两个可见块时仅按已有跨度（含“更多”）分配整行宽度，单块仍保留基础列宽；该显示分配不改变准入容量或滑条宽度门槛。
3. 滑条至少占两列且有独立的最小可操作宽度；首版优先放在长卡底部。标准卡无法满足宽度时不提供该选项，不把它压进一个小格。
4. 单行插槽按列跨度计算容量，不把一个跨两列的滑条算成一列。首版不支持跨行、自由坐标或用户任意改变块尺寸。
5. 底部区域高度固定；空值显示占位，不能因为等待数据、变离线或数值变长改变卡高。完全未配置小块时保留简洁的空底部，不自动挑选第一个可写能力。
6. 长卡缩回标准卡保留额外配置，不删除绑定，也不为了容纳它们偷偷恢复长卡或增加第二行。

### 窄屏与大字体

二至四列是有界布局能力，不是强制在所有半宽卡片塞入四个控件。可交互区域以至少 44 CSS px 的宽高作为首版触控检查基线，同时检查系统大字体下的值和单位。

- 设置面板只允许添加当前布局能完整容纳的块或跨度，并显示剩余容量。
- 对既有配置遇到变窄屏幕、放大字体或从长卡切回标准卡的情况，保留全部配置；显示可容纳的前部小块，末列必要时使用“更多”入口承接溢出。
- 日常模式的“更多”进入现有设备页，编辑模式进入同一个卡片设置面板；不新建第二个控制页面。
- 不自动换行、不横向滚动、不缩小触控目标、不为塞满内容强行缩字体。底栏不显示功能名称，但须保留完整的可访问名称和设置面板名称；数值与单位优先完整可读。
- 四列效果未通过目标手机的视觉与触控检查前，只开放实际通过的列数，不把四列写成无条件产品承诺。

### 状态与离线样式

状态颜色与卡片尺寸分开计算，不能继续用简单的 `!online` 同时决定布局、名称颜色和操作权限。

| 证据状态 | 右上角展示 | 设备名及操作 |
| --- | --- | --- |
| 已认证本地链路就绪，或现有云状态已同步 | 对应实际通道图标，绿色 | 名称正常；能否操作另取权限、能力与新鲜状态门槛 |
| BLE 在附近，或云端在线但未同步到可操作状态 | 对应通道图标，蓝色 | 名称正常；不得把“在附近”当已连接 |
| 已有明确不可达证据且无其他可用通道 | 灰色图标 | 名称变灰；缓存读数不冒充实时值 |
| 尚未取得可达性证据 | 中性图标，详情为状态未知或未发现 | 不把未知伪装成已确认离线 |

BLE 发现继续使用现有认证标识匹配与 TTL，不按 MAC、广播名或“扫描已启动”判定在线。双模式设备的 BLE 不可用但 Cloud 仍在线时不能整卡变灰。分享只读用户没有写权限，也不等于设备离线。

状态图标优先简洁显示，当前提供可访问名称和 title；点击后的通道详情尚未实施，列为非阻塞后续展示增强，不混入本轮最小收口。无实际通道证据时不显示“已连接”。不为刷新首页图标新增扫描器或连接全部设备。

## 编辑与设置流程

### 页面级编辑

长按卡片主体或设备图进入编辑，顶部只显示左侧 ×、右侧 ✓，分别提供“取消编辑”和“保存卡片”的可访问名称，操作区至少 44×44 px。去掉“编辑设备卡片”、顶部选中设备名以及“标准卡／长卡／设置内容”整栏，编辑态也不保留空的房间栏占位。尺寸及内容设置仅在既有统一面板中显示。

编辑态直接拖动卡片任意主体位置即可排序，不要求点击右上角或再次长按；轻点卡片打开设置，轻点小块定位到该块。按下候选不等于真正拖动：只有实际移动启动排序后才屏蔽落点尾随点击，不能吞掉普通轻点。键盘聚焦整卡后使用上下方向键排序，不再显示专用拖柄。

| 操作 | 日常模式 | 编辑模式 |
| --- | --- | --- |
| 点击卡片名称、设备图或空白 | 进入设备页 | 打开卡片设置 |
| 点击读数块 | 进入设备页查看该设备 | 设置该块 |
| 点击开关、按钮 | 沿原链路执行明确操作，不跳转卡片 | 只打开设置，绝不发设备命令 |
| 拖动滑条 | 本地预览，释放后提交一次 | 不调值、不执行，改用点击进入设置 |
| 拖动卡片主体或设备图 | 不提供排序 | 只改变草稿顺序；松手不误开设置 |

长按、拖卡、滑条、房间横滑和下拉刷新只有一个手势所有者。普通态保留纵向浏览；编辑态卡片主体由排序拥有触摸，背景／间隙仍可纵向滚动，拖到边缘沿用 Sortable 滚动。进入编辑后冻结当前顺序，暂停房间横滑与下拉刷新；退出、销毁或挂起时释放手势锁。长按后产生的点击不得进入设备页或补发命令。不为此次修正新增持续抖动动画。

### 取消和保存

编辑草稿包含当前视图顺序、各设备尺寸和小块绑定，与原始数据分离。当前 Sortable 可以保留，但 `onEnd` 只能更新草稿，不能调用现有立即保存路径。

- 取消直接丢弃本批草稿，不改设备、不写远端配置，也不删除旧偏好。
- 保存前校验设备仍可见、能力绑定及当前账号上下文；异步结果使用现有账号会话隔离，不能写进后来登录的账号。
- 保存成功后才切换已保存基线并退出；失败保留草稿，显示未保存并允许重试。保存期间禁止重复提交及继续拖动。
- 返回键或主动离页遇到未保存修改时确认放弃；进入后台不自动保存，释放手势与有限控制作用域，返回后可继续仍有效的内存草稿。
- 账号、服务地址或设备访问权限变化时使相关草稿失效；分享撤权不能因本地草稿继续显示有效操作入口。

### 小块配置入口

主入口为“长按编辑 → 点击卡片或小块”，不再提供重复的顶部“设置内容”。统一面板提供标准／长卡尺寸、块类型、能力选择、顺序、移除与清空，显示单行预览及当前可容纳列数。类型默认为只读；开关、按钮、滑条须用户明确选择，候选同时受 Manifest、共享权限、容量和宽度约束。

设备设置中提供“首页卡片”作为第二入口，复用同一个配置面板与草稿逻辑；不要求进入同事的自定义控制页编辑器，分享只读用户也可设置自己的本机展示。首页面板的“完成”只更新外层草稿，最终以首页取消／保存为准；第二入口建立单卡会话，使用面板取消／保存，不回写全部设备或房间顺序。两条入口均不边改边落盘，存储失败保留草稿并允许重试。

长按产生的尾随点击不立即弹出面板；打开面板后暂停卡片拖动。每次面板有独立代际，旧弹窗关闭事件不能取消后继面板。Ionic 缓存设备设置页离开、同组件切换设备 ID 或账号／可见性变化时关闭旧会话；进入后台保留仍有效的草稿，禁止修改与保存，不启动任何连接。

## 数据与控制复用

### 绑定和名称

小块只保存逻辑设备身份及能力引用，能力引用以现有 `key + kind + type` 核对，不按数组下标、昵称、MAC 或广播名绑定。

- 数据块只选择当前授权可读的标量 Property，使用已有 State 快照；`0`、`false` 是合法值，缺值显示 `—`。
- 开关只绑定现有可写布尔 Property。滑条只绑定已有控制链支持、且具备有效范围和步长的数值 Property，复用原有限值、范围与 step 校验。
- 按钮仅提供现有链路已支持、参数可明确验证的 Action；不允许在偏好中保存任意命令 JSON，不为首页扩展新的 Action 协议或参数编辑器。
- 设备名、能力名、布尔文案和单位复用 `display-metadata` 与 Manifest；卡片配置不建立另一套全局昵称或单位转换系统。
- 缺少已授权 Manifest 时引导先进入设备读取能力，不自动连接列表中全部设备。能力被删除、类型改变或权限撤销时保留可识别的无效绑定提示并禁用，不静默改绑其他属性。
- 数据失去新鲜性时用统一的缓存样式或状态说明，不编造更新时间，不为了首页读数开启持续 Telemetry。

### 控制与作用域

DC4 按以下合同接入，DC3 及旧偏好保留只读语义，不因字段可写自动变成控制块。

`DeviceUiPort.sendCommand()` 已有 BLE、LAN 和 Cloud 路由，但它不是完整的首页控制协调器。复用设备页现有的权限、能力、State 新鲜性、单字段 pending、会话隔离及未知结果保护，必要时抽出小型公共协调器，不复制整页逻辑。

1. 首页浏览只订阅已有展示状态，不为每个卡片建立本地连接。只有用户明确操作对应小块时，才按现有协调器取得有界的目标设备作用域。
2. 本批操作结束、离页、后台或进入编辑态，释放本批持有的作用域；不能关闭其他页面或后继操作仍持有的连接。底层 BLE 是否保留由既有连接所有者决定，不另定全局断连策略。
3. 可达性不等于写权限。操作前仍校验分享权限、端点权限及新鲜 State；不能用缓存 `false` 推导一次反转，也不能把只读分享配置成可写。缺少新鲜 State 时明确显示“连接以操作”，首击仅准备有界作用域和同步，连接完成不暗中补发原点击，后续由用户明确操作。
4. 滑条拖动只做预览，松手提交一次，手势取消不提交；开关和按钮防重复点击。编辑态禁用命令及待提交预览，退出编辑不能发出残留操作。
5. 沿原链路区分 pending、ACK、新鲜 State 和 UNKNOWN。ACK 不冒充物理动作或新鲜状态，失败或结果未知不自动重放；完整请求记录继续保留。

## 模块与持久化

保持少量清晰职责，实施时沿现有组件落位，不为了配置面板再建一套首页业务框架。

| 模块 | 职责 | 不负责 |
| --- | --- | --- |
| 卡片展示模型 | 从偏好、名称、能力、状态生成固定单行槽位和状态样式 | 发命令、扫描、存储 |
| 卡片组件 | 渲染和输出点击、编辑及操作意图 | 保存配置、选择传输协议 |
| 列表编辑状态 | 草稿、拖动、取消、保存及父级手势协调 | 改设备身份、共享权限或房间成员 |
| 首页偏好存储 | 有界校验、版本化本地记录、按账号隔离和一次保存 | 设备业务配置、跨手机同步 |
| 公共控制协调 | 复用原权限、连接作用域、命令及 ACK/State 保护 | 第二套执行队列或通信协议 |

第一阶段按 `authority + accountId` 隔离本机首页偏好，卡片按逻辑设备 ID 保存。现有房间只有列表下标和名称，没有独立稳定 ID：当前使用“全部设备”或精确房间名称的编码作为视图键，不使用易变的列表下标；房间重命名按新视图回退，不猜测迁移旧顺序。复用现有账号作用域工具和存储设施，同一版本化记录保存本批偏好，避免本地布局和远端排序分开提交造成假取消、部分保存。

DC4 使用 v3 记录：revision、设备尺寸、视图排序及按设备保存的 slots。引用为 `key + kind + type`，可选 mode 为 read／toggle／action／range，省略即只读。v1／v2 仅在内存投影到 v3，保留尺寸、顺序、revision 和旧引用的只读语义；用户保存才一次升级写入，读取／取消零写入。每设备最多四个引用且总跨度不超过四列，range 占两列。未配置时兼容读取旧 `config.card.metrics`，显式 `[]` 保持空白，不回退旧绑定。

旧 key-only 引用仅在已有授权 Manifest 可完整核对时导入子草稿；任一引用无法解析或旧配置超过四项时保留原配置，不截断或转为空。用户可先进入设备页获取能力，或明确清空后重新配置。类型、角色或读取权限变更时保留原完整引用、显示不可用及占位，不按相同 key 静默改绑。

本地保存先比较读取时的原始记录，再一次写入完整记录；这是陈旧快照检查，不是跨窗口原子事务或数据库 CAS。记录损坏、未来版本、存储不可读／不可写时不清空或覆盖原记录，写入失败保留内存草稿。偏好不保存 Manifest、State、数值、凭据或网络参数。

未有个人排序时沿用现有列表基线；保存过个人顺序后优先使用该顺序，新增设备按稳定规则附加。原云端顺序、房间成员和相关 CAS 不回写、不清除；未来若需要跨手机同步，另接用户偏好接口，不借用旧 V1 `saveUserConfig` 或设备 owner 配置接口。

已有 `config.card` 仅作为未配置时的兼容读取来源，经过相同校验后转换；显式空配置与“未配置”要区分。所有当前消费者核对完成前不删除旧类型或测试页面。首版不保存任意命令、凭据、网络参数、设备 State 或完整 Manifest 到卡片偏好中。

### 本批已复现缺陷与最小修正

第二入口真实保存后，存储记录已变为标准卡，但返回首页仍显示长卡；再次长按时才读取新记录。原因是设备设置和 Ionic 缓存的首页各自持有 Editor，单卡保存不更新首页旧的内存快照。同一 WebView 的 localStorage 写入不会自动向当前窗口发出 storage 事件。

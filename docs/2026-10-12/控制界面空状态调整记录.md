# 控制界面空状态调整记录

## Intent：最终目标

将没有控制组件时的自动引导遮罩替换为居中的“控制中心配置”入口。

## Data：可用证据与执行细节

- `layouter2.ts`：移除 `loadLayouterData()` 的空 dashboard 自动 `showGuide()` 调用，导入 RouterLink。
- `layouter2.html`：在加载完成、dashboard 为空、普通控制模式且具有布局编辑权限时渲染配置按钮。链接使用当前路由的设备 ID，目标为 `/device-manager/:id/uic`。
- `layouter2.scss`：空状态覆盖布局器内容容器，以 Grid 的 `place-items: center` 实现双向居中，保留 24px 内边距。
- 空状态分支不创建空的 Gridster 网格，避免其布局行高撑大空白区域。
- 非空布局和编辑模式继续创建原有 Gridster；`ViewChild(Gridster)` 原本可选，现有刷新调用已处理其暂不存在的情况。
- 本地 local 开发服务自动重新编译成功，耗时 1.815 秒，并向客户端发送页面重载通知。
- `git diff --check` 通过；忽略空行后的差异复核确认仅引入上述行为变化。

## Edges：边界与限制

- 没有新增测试，没有调用浏览器检查 UI。
- 没有修改设备配置或数据库，没有扩大到 V2 设备能力状态、默认布局生成和组件预览页。
- 共享设备继续沿用无布局编辑权限的规则。
- 保留显式调用旧向导的原有代码；本次取消的是空布局加载时的自动弹出。

## Answer：交付与成功标准

设备控制页在空布局时显示“控制中心配置”，点击进入当前设备的“界面配置”页。编辑模式不显示该空状态入口，仍可通过组件工具栏添加组件。实现及 Angular 模板、样式编译已经完成。

架构图、数据流图和执行计划见《控制界面空状态调整计划》。

## 自我复核

- 从触发条件移除了自动弹窗，没有用额外遮罩隐藏它，也没有用设备名称或 ID 做特殊处理。
- 复用了既有配置路由和编辑权限判断，没有新增导航服务或额外页面。
- 居中依据设备内容容器，避免以桌面浏览器窗口高度计算导致嵌入式手机预览错位。
- 已验证编译和变更范围；最终视觉位置及点击体验未进行浏览器验证，不将构建通过等同于视觉验收。

# 布局预览组件统一记录

## Intent：最终目标

统一界面工作室与组件预览页的组件实现，消除经典协议设备布局预览仍使用简化卡片的问题。

本记录描述早期排查。用户随后澄清，实际要求是“始终展示真实设备字段，套用完整组件预设”；只统一渲染器和尺寸未完成该要求。最终配置共享的实现与验证见[真实字段套用组件预设记录](./真实字段套用组件预设记录.md)。

## Data：执行细节与证据

### 根因

组件预览页使用共享 PageLayoutPanelComponent。工作室按设备协议分流：新版设备复用共享组件，经典协议设备由页面自身的 HTML 和 SCSS 模拟开关、按钮、滑块、数值及输入框，因此同类组件外观不同。

用户随后提供 15:31:57 的截图，显示已经是共享组件，但每个开关、按钮和读数占据整行。进一步定位到第二个问题：capabilityTiles 丢弃共享默认布局的尺寸和变体，arrangeTiles 又统一覆盖为宽 4 或宽 8；变体尺寸归一化与窄屏扩列后，常用卡片都被放大。

### 实现

- 新增局部适配文件 legacy-preview-cards.ts，将经典协议已有的真实字段和组件配置转换为共享面板的 PanelCard。
- 读取协议已有的原始值、swi/switch、val/value 和范围约束；开关转换为布尔值，数值转换为有限数值，缺失数据保持缺失。
- 组件变体及合法尺寸使用共享 widgetVariant、fitSize 和 reflowPageWidgets，不复制组件预览页的演示数据或样式。
- 工作室经典协议分支接入 PageLayoutPanelComponent，删除手写简化模板及其专用样式。
- 新版分支补齐附属读数到 PanelCard.extras，避免布局已有的附属字段在预览中丢失。
- 保留面板默认只读模式、440px 内容高度上限、内部滚动与 12px 外层内边距。
- 后续修正 capabilityTiles，保留 generateDefaultPageLayout 返回的 grid.width、grid.height 和 variant。
- arrangeTiles 只调整主题排序与强调状态，不再覆盖组件尺寸。截图中的开关、按钮、读数按默认规格宽 2 排列，窄屏由共享面板正常扩为半行。
- 同步已有尺寸断言及混合宽度排布断言，没有新增测试用例；尺寸归一化仍遵循共享组件的合法尺寸。

### 验证

- `npm run build:local -- --progress=false` 通过，完成 TypeScript、Angular 模板和样式的完整应用构建。
- 工作室现有 device-uic.page.spec.ts 的 22 项检查全部通过，覆盖预览、生成、风格切换、取消、设备能力变化及应用保存等现有流程。
- 检查使用临时 TypeScript 配置限定已有 spec 范围；首次使用绝对配置路径被 Angular 路径解析拒绝，改为工作区相对路径后成功，临时配置均已删除。
- `git diff --check` 通过。
- AST 核对两个页面均使用 app-page-layout-panel，滚动容器高度仍为 440px。
- 用户反馈后检查运行进程：4200 的 ng serve 来自当前工作目录，使用 local 配置。直接读取 main.js 指向的工作室模块，确认其含新适配器且不含旧简化卡片模板，响应为 HTTP 200、Cache-Control 为 no-cache。
- 尺寸修正后再次完整构建成功，工作室页面 22 项和布局适配器 8 项现有检查全部通过，共 30 项。
- 再次从运行服务的路由入口读取当前工作室模块，确认输出保留 widget.grid.width、widget.grid.height、widget.variant，arrangeTiles 已不再写入统一宽度。此次核对的是实际 HTTP 响应，并非只检查磁盘构建目录。

## Edges：边界与限制

- 未新增测试用例，未调用浏览器进行 UI 验证，未向设备发送指令。
- 本次只统一工作室的布局预览。经典协议设备应用后的界面仍由原有 Layouter2Component 渲染；没有把经典协议设备迁移为新版协议。
- 组件预览页的示例数值、图表历史和可调选项不注入真实设备预览；同一组件的状态、尺寸和配置仍由设备与当前布局决定。
- 经典编辑器一瞥和风格卡片属于示意内容，继续保留原有实现。
- 现有 22 项检查主要覆盖工作室流程，不能代替新适配器全部经典协议数据形态的实机和视觉验证。

## Answer：交付格式与成功标准

工作室支持的经典协议组件已通过局部适配接入共享组件库，新版设备继续使用相同渲染入口并显示附属读数。初始预览保留共享组件默认尺寸和变体，主题切换不再将卡片统一放大。应用构建和 30 项现有检查通过，实际开发服务已返回修正后的模块。

架构图、数据流图和实施边界见同目录《布局预览组件统一计划》。

## 自我复核

- 修复协议分支造成的组件实现分叉，未通过调整旧卡片样式来模拟组件库。
- 没有复制示例数据，也没有构造伪造的已确认 Manifest；适配只发生在只读预览边界。
- 适配器复用现有组件规格，新增代码集中在单一职责文件，没有改动共享控件或设备保存流程。
- 保留经典协议应用后的渲染差异作为明确边界，不把本次预览统一描述为设备界面的完整迁移。
- 首次排查仅发现经典协议渲染分叉，尚未掌握用户截图，却提前将其视为主要根因，定位不充分。后续结合截图和运行服务响应，补查输入配置链路，修复默认尺寸在中间层被覆盖的问题。
- 共享组件的使用、组件输入配置正确、开发服务内容更新是三个不同的验证层次；本次后续复核分别给出证据，没有再将源码引用了组件库当作全部问题已解决。

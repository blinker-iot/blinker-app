# 真实字段套用组件预设记录

## Intent：最终目标

按用户最终确认的要求，始终展示真实设备字段，并套用“组件预览”页已有组件的完整可复用预设。

## Data：执行细节与证据

### 共享配置

- 从组件预览页的 46 个既有示例中提取类型、变体、推荐宽高和可复用 options，存放到 core/device-v2/widget-presets.ts。
- 组件预览页通过稳定的 preset 标识引用这些定义，示例数据仅保留标题、字段约束、数值、历史和示例专属配置。
- 所有示例均使用“共享预设 options + 原有示例专属 options”，避免抽取过程中改变组件预览页的展示配置。
- 为 21 种组件变体显式指定一个现有默认预设。默认选择不读取字段名称，不按用户截图中的 demoPower、pressButton 等键名硬编码。

### 工作室接入

- capabilityTiles 从共享预设取得初始组件变体与推荐尺寸。
- toPageLayout 将整个 preset.options 写入布局，随后合并 AI 显式指定的图标和色调；不再仅输出 icon/tone 两个字段。
- 页面预览、AI 视觉捕获和新版布局保存均经过这条转换，配置保持一致。
- 经典协议的只读预览适配器也从同一目录读取完整预设 options。
- 具体默认示例：开关使用继电器磁贴的插头图标、浅色填充和箭头角标；动作使用校准组件的卡片形态、青色色调和执行计数；数值使用大数字组件的芯片图标、橙色色调和变化量显示。
- 真实字段的标题、绑定键、值、单位、范围、步长和权限仍来自设备与当前布局。

### 验证

- `npm run build:local -- --progress=false` 完整构建通过。
- 已有工作室页面检查 22 项、布局适配器检查 8 项、生成服务检查 6 项全部通过，共 36 项；未新增测试用例。
- 对全部 46 个预设进行结构校验：类型与变体兼容、宽高符合共享规格、options 符合现有白名单；21 个默认变体映射全部有效。
- `git diff --check` 通过。
- 直接读取 4200 服务的 main.js，再读取它引用的工作室和组件预览模块；两者均返回 HTTP 200，并分别从同一个共享 chunk 导入 presetForVariant 与 WIDGET_PRESETS。

## Edges：边界与限制

- 用户选择的是真实字段套预设，未替换为示例画廊，未注入演示设备的读数、历史、GPIO 说明、告警阈值、状态映射或数字格式。
- 模拟历史与真实历史是不同数据来源；未为真实设备生成演示曲线。
- 工作室按兼容变体选用既有默认预设；AI 仍通过既有类型、变体和尺寸字段编排，没有扩展服务端协议或增加预设选择控件。
- AI 指定的合法变体、尺寸、图标和色调仍可覆盖对应的默认展示配置。
- 经典协议的设备保存格式和实际设备页渲染器不变，本次仅为其工作室预览套用共享预设。
- 未调用浏览器进行 UI 验证，未实际应用布局到设备。

## Answer：交付格式与成功标准

组件预览页和工作室现在直接引用同一份预设配置。工作室输出完整的可复用外观和交互选项，并继续绑定真实设备字段；预览、视觉捕获和新版保存保持一致。构建、36 项现有检查及实际开发服务模块核对均通过。

架构图、数据流图与实施边界见同目录《真实字段套用组件预设计划》。

## 自我复核

- 前两次把用户所说的“预置组件”分别误解为底层渲染器和卡片尺寸，未验证配置层是否一致，结论过早。
- 本次先确认“始终使用真实字段并套完整预设”，再围绕单一配置来源修改，没有继续用尺寸或颜色微调替代预设接入。
- 预设来源是已有组件预览目录，配置被搬到共享文件后由两页引用，没有生成第二套外观，也没有把示例中的设备事实绑定到用户设备。
- 完整可复用预设与示例专属事实保持清晰边界；保留数字格式和告警阈值等真实字段语义，避免为了视觉相似而改变读数含义。
- 编译与模块检查证明实现和服务内容已更新，但不等同于浏览器视觉验收，未将后者宣称为已完成。

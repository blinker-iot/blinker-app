# 界面工作室自主布局记录

## Intent：最终目标

去掉界面工作室的布局节奏选择和可用组件列表，由 AI 根据描述、主题与设备能力自主编排。

## Data：执行细节与证据

### 前端

- 删除“选择布局节奏”与“可用组件”列表的模板和专用样式。
- 删除 densities、density、chooseDensity 状态与方法，移除主题元数据中关联的 density。
- 生成、微调方法及 HTTP 请求不再接收或发送 density。
- 自动适配及生成前的本地预览沿用基本排布；AI 返回布局直接用于预览和应用，不再被密度切换重新排列。
- 保留 sourceTiles 和 manifest 作为实际设备字段及合法组件的依据。

### 后端

- workflowRequest 将 density 改为可选兼容字段，生成与微调共用此契约；设计模型输入移除 density。
- 旧版生成接口接受不含 density 的请求；旧客户端仍可提交合法枚举，但模型输入只包含 prompt、style、widgets。
- 旧版运行提示词删除主题绑定的 balanced、compact、focus 规则，改为按用户需求和组件用途自主安排。
- 保留字段身份、读写权限、合法尺寸、去重及输出结构校验。

### 验证

- Angular 开发服务重新编译成功，并推送页面更新。
- Docker 构建成功，包含 Gateway TypeScript 编译、AI 服务严格类型检查和 Rslib 构建。
- 本地 Gateway 与 device-ui-agent 已更新，两个容器均 healthy，网关健康接口返回 HTTP 200。
- 从运行容器读取编译产物，确认 density 已为可选字段；AST 检查未发现模型输入继续读取 request.density。
- 后端现有界面生成检查：22 项通过，1 项 PostgreSQL 集成检查因未配置测试数据库跳过。
- 前端定向检查：页面 22 项、请求服务 6 项全部通过；布局适配器 8 项中 7 项通过，1 项网格坐标断言失败，合计 35/36。
- `git diff --check` 在两个仓库均通过。

## Edges：边界与限制

- 未新增测试用例；仅同步已有测试的方法参数和被移除功能的断言。未使用浏览器 UI 验证，未发起真实模型生成。
- 首次 Angular 测试构建读取全部 spec，遇到无关 BLE 测试导入不存在的 BleDirectFrameChannel、BleDirectProtocolError；随后使用临时配置只编译工作室现有测试，临时配置已移除。
- 剩余网格断言期望数值卡片能以宽 8 独占一行，当前外观尺寸归一化会将它缩为合法宽度并成对排列。该用例输入全为 value，本次移除密度前后其初始宽度均为 4；本次未修改尺寸规则或为了通过检查改变该断言。
- 不删除真实设备能力约束，不虚构字段，不放开不兼容的控件尺寸和控制权限。
- 仅更新本地 Gateway 与生成服务容器，未重建数据库、Redis 或 Broker，未修改设备配置。

## Answer：交付与成功标准

页面已移除两个区域，前后端已使用不携带固定密度预设的生成链路。刷新工作室即可使用；AI 会依据当前描述、主题和设备能力编排界面。

计划、架构图和数据流图见同目录《界面工作室自主布局计划》。

## 自我复核

没有只隐藏控件再暗中发送 balanced 默认值，也没有以“让 AI 判断”为由删除设备绑定校验。此次同时处理页面、请求和模型提示，并更新实际运行容器，避免再次出现源码已改而容器契约仍旧的情况。构建、相关检查和服务健康已验证；保留已发现的无关测试问题，不宣称所有检查或完整模型链路均通过。

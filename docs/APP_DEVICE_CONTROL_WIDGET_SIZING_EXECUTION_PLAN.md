# 设备控制组件尺寸与预览一致性执行计划

更新日期：2026-10-23。范围：现有设备控制组件、手动编辑器及 Agent 原子组件；不涉及设备列表卡片重设计。

后续修正：本文件的固定78／84px行预算、整行原子内容自适应及560px断点是历史基线，不再是当前尺寸合同。以[页面覆盖与组件几何修复计划](APP_UI_GEOMETRY_AND_COVERAGE_REPAIR_PLAN.md)及[当前规范](APP_UI_DESIGN_SYSTEM.md)为准：2×2实际方正，每个网格独立测量，原子外框随行数改变；不改写保存数据。

## 1. 目标与边界

统一尺寸语义和同类组件的对齐，不把所有组件强制做成同宽同高。复用现有组件、主题、Manifest/State、布局保存和 Agent 链路，不新增协议或依赖。

- 已保存布局的 grid、组件 ID、顺序、绑定、选项不自动迁移或重新套预设；只读打开无写入。
- 新建／尚无保存布局的默认规格使用同一份组件预设；用户显式尺寸仍有效。
- 保留整行内容自适应与绘图区 `fills-rows` 的区别，不恢复无意义的空白撑高。
- 历史尺寸的显示适配不能用放松新布局校验、裁切交互或重叠热区替代。
- 不改变控制权限、作用域、ACK/State/UNKNOWN 或编辑态禁控语义。
- 本轮不部署、不刷板、不提交或推送；保留其他本地修改。

## 2. 排查基线

当前有 48 个共享预设；均符合允许尺寸表。普通 V2、兼容面板及 Agent 原子组件已复用组件本体，不需另建一套模板。

公共网格为 8 栏：常规行基准 84 CSS px、间距 12 CSS px，紧凑行基准 78 CSS px、间距 10 CSS px。紧凑容器下原宽度 2 对应半行、4/8 对应整行；整行内容高度不承诺与绘图区等高。

已通过实际 SCSS 与代表性静态 DOM 的隔离检查确认以下缺口；这不是手机现场验收：

| 缺口 | 证据／风险 | 最小处理 |
| --- | --- | --- |
| Stepper 2×1 溢出 | 358px 内容容器中卡宽 174px，标题被压至零宽，右侧加按钮越界 | 按局部可用空间适配，不修改历史 grid |
| Slide 4×1 溢出 | 720px 内容容器中卡高 84px，滑轨被压至约 27px，40px 滑块被裁切 | 单行紧凑排布并保留操作空间 |
| Number 2×1 重叠 | 默认大读数与标题纵向预算冲突 | 单行专用读数排布；多行保留原层次 |
| 默认规格漂移 | 基础生成与自动模板分别选择尺寸／选项 | 共享预设作为新建唯一来源 |
| 预览口径漂移 | 编辑器强制 compact；实际面板按容器；Agent 按 iframe 视口 | 公共内容容器、断点与栏数语义 |
| 独立小控件热区不同 | 发送、加减、开关视觉尺寸不一 | 分离视觉与有效点击区域，保持间隔 |
| 旧尺寸编辑兼容 | 旧 schema 可读，但整页严格编辑校验可能拒绝未改部件 | 只继承匹配原部件的历史尺寸，不放宽新建 |
| 错误行挤占控件 | 78px 小卡遇到错误提示后，实际组件可缩至 57px，重新裁切按钮／重叠读数 | 仅反馈态让渲染行容纳组件与正常流错误文本，不改保存 grid |

## 3. 执行顺序

### WS1：尺寸溢出与历史兼容

- 局部修复 Stepper、Slide、Number 的窄／单行排布。
- 允许修改其他部件而不丢弃未改历史尺寸；仍校验边界、重叠、字段兼容及新尺寸。
- 不通过批量重排、变更旧 grid 或缩小有效操作范围解决溢出。

### WS2：新建默认规格

- 普通生成与自动模板复用现有默认 preset 的尺寸和选项。
- 消除重复默认表；必要的绑定判断提取为纯模块，避免循环依赖。
- Agent 继续引用同一目录；已保存文档不重新生成。

### WS3：编辑预览口径

- 正式页面、编辑画布、属性预览及 Agent 原子网格使用相同的内容容器断点。
- 宽度显示实际栏数，不将 4 栏和 8 栏无条件混称“整宽”；说明手机紧凑映射。
- 高度说明为布局行预算，内容卡与绘图卡可按用途不同。
- 选择框／拖动的视觉辅助不改变保存坐标、顺序或绑定。

### WS4：触控区域与同类对齐

- 本批重点为加减／发送、开关和滑动开关；共用样式变更需核对消费者。
- 48 CSS px 是本项目 WebView 内部目标，不等同于 iOS pt 或 Android dp 的认证结论。
- 保留视觉层次，确保有效热区不重叠、未被 overflow 裁切，保留键盘名称／焦点与禁用语义。
- 不顺带重做其他组件或替换主题字体。

## 4. 有限回归及验收边界

1. 纯逻辑：新建默认来源一致；所有既有预设合法；历史布局往返、排序及绑定保留；新部件不可借历史豁免绕过校验。
2. 组件：编辑／布局态、属性预览和 Agent 只读预览不发送命令；显式进入真实控制预览的既有权限与命令行为不变。本次展示元数据不影响控制输出。
3. 隔离浏览器：实际 SCSS、代表性内容，在小手机 375px、大手机及横屏／720px 内容宽下检查三项溢出、断点两侧、热区和互不重叠。
4. 三主题与长标题／数值，开启 reduced-motion 检查几何；原生手机的放大文字、触摸手感及完整 Agent 生成另作短验，不将隔离 DOM 结果当作这些验收。
5. App／Agent 编译与必要定向测试；不调用真实服务或设备，不重跑无关业务长循环。

### 5.1 实施结果

- Stepper：单行局部容器适配，窄卡标题与操作分行；窄多行采用已有 split 视觉排布。显示与操作区域分开，不改变属性直接提交、动作先选值再发送的原语义。
- Slide：单行左标题／状态、右轨道；轨道固定保留 56px 操作高度，40px 可见滑块位于 48px 实际目标内，不再纵向裁切。
- Number：仅单行使用紧凑标题／26px 读数／备注规则；两行及以上保留原读数层级，原始完整读数仍在可访问名称中。
- Toggle：sm/md/lg 视觉轨道保留，有效目标不少于 48×48 CSS px；Stepper 独立加减／发送也使用 48px 实际区域。未放大全局 `.rbtn`，避免影响旋钮等其他消费者。
- 错误提示：正式面板与真实控制预览仅在有反馈时让渲染行自然容纳组件和错误文本；错误不覆盖控件，不改变保存 grid。full/compact-wide 保留内容自适应。
- 默认来源：删除重复 `DEFAULT_SIZES` 和自动模板二次套预设；提取纯绑定判断模块消除循环依赖，保留原导出。普通生成、手动目录和 Agent 使用同一默认目录。
- 历史兼容：仅匹配原 widgetId、类型、绑定及原宽高、且没有新 variant/options/extra 的原 schema-1 部件继承尺寸；仍执行边界、重叠和字段兼容校验。显式调整尺寸才执行 fit，不因打开属性页而归一化旧尺寸。
- 预览：普通页、编辑画布、属性预览及 Agent 按具名内容容器切换；普通兼容面板也使用公共 720px 外壳。编辑／预览使用保存坐标，仅既有拖动态自动排布。移除两列宽度折叠旧逻辑，显示实际栏数与简短预算说明。
